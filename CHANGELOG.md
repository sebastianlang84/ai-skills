### Added

- Added `codex-call`, one script that pins every Codex call: `gpt-6-sol` at `medium`, read-only sandbox, hooks off, thread kept. `new`, `resume <thread>`, `--detach` plus `wait` (exit 3 = still running, under the 600 s tool cap), a per-call record in `~/.agents/state/codex-call/`, and a `selftest` that runs new, an immediate resume and a sandboxed write against the live CLI. Verified with codex-cli 0.155.1 on 2026-09-22. Measured reasons for the pins: `--ephemeral` makes a thread unresumable; this host's SessionEnd compaction hook holds a thread's writer lock for over 240 s; `resume` needs the model repeated and takes its sandbox only as `-c sandbox_mode=…`; a failed turn exits 0. Chosen over the official Codex plugin and an MCP server after a measured debate (`~/peer-debates/2026-09-22-codex-skills-vs-mcp/`): about 110 tokens per session against ~451 for the plugin; an MCP stub saved 88 tokens at the cost of a resident process.
- Added `peer-debate`, which runs two `agy` conversations under asymmetric proposer/refuter roles: blind opening turns execute concurrently, later turns relay in order until both sides converge or four exchanges are exhausted. It records persistent conversation ids, transcripts and token counters, rejects soft-denied or forked Agy results, and deliberately grants the full configured Agy tool surface without terminal sandbox or permission prompts on this private experiment host.
- Added `evaluating-with-promptfoo`, which turns Promptfoo from an ad-hoc CLI into a reproducible local evaluation workflow: frozen cases and runtime, functional outcomes separated from provider-specific instrumentation, pinned isolated execution with sharing and telemetry disabled, raw evidence in `wasti-research`, and one directly readable result row in the Brain. It deliberately leaves experiment design and one-lever tuning to `autoresearch`.
- Added `using-brain`, the shared workflow for progressively retrieving and durably extending the machine-wide Brain across Codex, Claude Code, and Pi. It keeps exact lookup ahead of ranked retrieval, separates current authority from Brain synthesis, locks shared writes, preserves provenance and trust, and routes retrieval changes through frozen measurement rather than adding a database or index by intuition.
- Added `cross-vendor-review`, which existed in the working tree since 14.08 but had never been committed — and gained the rule it was missing: **when to stop.** An adversarial reviewer asked "is anything wrong here?" answers yes for as long as it is asked, and every fix affords new plausible objections, so "review until it finds nothing" is not a termination condition but an unbounded one. One round is the default; a second is justified only by a confirmed blocker whose fix was substantial, and its mandate is that fix — was it really fixed, did it break anything — not a fresh unbounded pass. Stop when the acceptance criteria stated *before* the work are met, the repo's gates pass, no confirmed blocker is open, and each confirmed defect left a regression test behind. For a design document there are no gates, so the spec carries the whole load and anything outside it is the weakest class of finding however compelling it reads. Measured in `market-digest`: eleven plan revisions across successive review rounds, several confirmed defects, one finding flatly wrong about what a source said — and zero lines built. Reasoning and the evidence ranking live in `~/.agents/brain/methods/review-silence-is-not-a-stop-criterion.md`.
- Added `parallel-agents`: coordinating several sessions on one repo, plus the hook that enforces the part a written rule kept losing. Worktree isolation prevents interference, not duplication — two sessions creating the same new file is invisible to Git until merge, which happened here to two sessions each following the isolation rules perfectly. A colliding creation is **denied**, naming the sibling file to read; the denial lifts when that file has actually been read (recorded by a `PostToolUse` hook on `Read`) and re-arms if it changes afterwards, because what was approved is specific bytes, not a filename. A plain retry stays denied. Only high-confidence evidence gates — a new addition in an attached sibling worktree, touched within a day — after a cross-vendor review showed that an all-history probe reports files deleted years ago forever. Opt-in per repo via `git config --local agents.duplicate-write-guard`, one 250 ms budget for the whole hook, and fails open on every error: a hook that breaks `Write` is worse than no hook. Ships `ownership.py`, which answers who holds which worktree and branch by joining `git worktree list`, the harness session files and `kill -0` — deliberately **not** a registry, because a claim file has to be written, refreshed and cleaned up and each of those is a way for it to lie. Pid reuse is checked against the recorded process start time. The write hook gates on that liveness instead of a file's mtime, so an abandoned worktree never blocks a legitimate recreation.
- Added `handoff`: compacts the current conversation into a document a fresh session — or a different harness — can resume from, covering state, decisions and their reasons, open questions, suggested skills, and Git state. Written to the scratchpad, never into a repo, with secrets redacted because the document gets pasted elsewhere. User-invoked.
- Added `resolving-merge-conflicts`: resolve an in-progress merge or rebase hunk by hunk, by tracing each side's original intent through commit messages, PRs, and linked issues rather than picking whichever side looks tidier. Adapted to this collection's approval gates — resolving is repair work, but finishing the operation is proposed and waits for the operator, and `--abort` is never the agent's call because it discards the resolution. Adapted from Matt Pocock's skill (MIT).
- Added `git-guardrails`: a `PreToolUse` hook that refuses irreversible Git commands before they execute, turning `git-workflow`'s prose rule into enforcement. It follows one rule — block the force variant, allow the guarded one: `push --force`/`+refspec`/`--delete`, `reset --hard`, `clean -f`, wholesale `checkout .`/`restore .`, `stash drop`/`clear`, `branch -D`, and `filter-branch`/`filter-repo` are blocked, while `--force-with-lease`, `branch -d`, `clean -n`, targeted `restore <path>`, `rebase`, and `commit --amend` stay available. Commit and tag messages are blanked before matching so prose cannot trigger a rule. Verified against 40 cases plus an end-to-end block in a live session.
- Added `diagnosing-bugs`: a six-phase discipline for hard bugs, flaky failures, and performance regressions. Its rule is that no hypothesis may be formed until one named command exists that has already been run and goes **red** on this specific bug — tight, deterministic, fast, agent-runnable. Loop recipes are written for this machine (curl against a running service, `docker compose run --rm`, the unit command from `systemctl --user cat` in the foreground, bisecting image tags), because system log access here is restricted. Adapted from Matt Pocock's `diagnosing-bugs` skill (MIT).
- Added `grilling`: the reusable relentless-interview loop, run before acting on a plan. Separates *facts* (the agent looks them up) from *decisions* (put to the user, one question at a time, each with a recommended answer), and ends on an explicit confirmation gate so nothing is built before shared understanding is reached. Adapted from Matt Pocock's `grilling` skill (MIT).
- Tracked `autoresearch`, `evaluating-local-tools`, and `releasing-pi-packages`, which existed in the working tree but had never been committed.
- Added `nightly-review-pipeline` to set up an unattended overnight review+fix pipeline (systemd/cron + bash orchestrator + headless `claude -p`) with bug and usability lenses, adaptive backoff, and safe auto-fix draft PRs (isolated worktree, tests-green gate, never main, never auto-merge).
- Added `code-documentation` to route documentation updates after code changes and keep PRD, README, changelog, TODO, AGENTS, and memory roles separate.
- Clarified the `code-documentation` goal so README, changelog, and TODO updates remain encouraged when they match each artifact's role.

### Fixed

- `git-guardrails` no longer refuses a merged-branch deletion just because the path carried a tilde. The exception resolved `-C` arguments literally, but the shell expands `~` before git sees them, so `git -C ~/dev/foo push origin --delete <merged-branch>` failed the directory check and fell back to the block — while the same command with an absolute path was allowed. It failed safe, but it cost a wasted attempt and read as the guard contradicting its own refusal message. Every refusal the guard exists for still holds: the default branch, a nonexistent directory, a compound command line (which can never be parsed safely and so is never eligible), and tag refs.
- Corrected the canonical global skill store path from `~/.pi/agent/skills` to `~/.agents/skills` across `README.md`, `skill-creator`, and `skill-creator/references/agent_adapters.md`. The old path does not exist on this machine, so the documented validation command could not run and `skill-creator` instructed agents to relocate skills to a missing directory, contradicting the global `AGENTS.md`.

### Changed

- `cross-vendor-review` now requires either an explicit request or a substantial, expensive-to-reverse decision with a named unresolved risk and a decision-changing possible verdict. Reviews default to one narrowly scoped `medium` round; the launcher accepts `REVIEW_REASONING_EFFORT` for justified escalation.
- `git-guardrails` now allows the one deletion it can *prove* harmless: removing a remote branch succeeds when every named branch is already contained in the remote's default branch. The commits survive in the base and the ref is recreatable from it, so nothing is lost — while refusing it unconditionally had a real cost, since merged branches could then only ever be cleaned up by hand, and one leftover ref held nightshift's throughput cap at zero for three nights. The check answers "no" whenever it is not certain: the sha comes from the live remote via `ls-remote` rather than a possibly stale remote-tracking ref, containment is an ancestor test so a squash merge stays blocked, a single unqualified ref voids the whole batch, and tags, the default branch, URL remotes, whole-repo push options, unknown options and any command line carrying a shell metacharacter remain ineligible. Every other rule is unchanged.
- `git-guardrails` now releases a branch the default branch has **absorbed**, not merely one it descends from — and grants the local forced delete the same exception, which previously had none at all. Ancestry was the only proof accepted, and a squash merge is not an ancestry relation: the change sits in the default branch byte for byte, under a commit that lists the branch nowhere, so every cleanup in a repository that squash-merges — most review flows — was blocked forever. Measured in `nightshift` on 2026-08-24: four squash merges, four refs the guard would never release, each needing the operator by hand. When ancestry says no, the guard now merges the branch into the default branch **in memory** (`merge-tree --write-tree`) and compares trees; an identical tree means the branch can no longer contribute anything the base lacks.
